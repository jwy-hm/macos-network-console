# Incident Report: Privacy Identifier Leak (2026-10-04)

## Summary

A developer's macOS username and a private LAN IP address were committed
to the public repository and remained in the published git history until
2026-10-04, when the history was rewritten and the remote refs were
force-updated.

The leaked values were:
- The developer's macOS username (a personal identifier)
- A private RFC1918 IPv4 address from the developer's local network

No passwords, tokens, API keys, or secrets of any kind were involved.

## Timeline

- P0 development: the identifiers were introduced as a test fixture while
  implementing the connection-monitoring feature (P0-12 / P0-13). The fixture
  captured real `lsof` output instead of placeholder data.
- 2026-10-04: the leak was discovered during review of PR #1 (Wi-Fi details).
- 2026-10-04: history rewritten with `git-filter-repo`; all remote refs
  force-updated; the `v0.1.0` tag was re-published against the rewritten tree.
- 2026-10-04: branch protection enabled on `main`.

## Root Cause

Two compounding gaps in the privacy-check tooling allowed the leak to pass:

1. **Scan scope was too narrow.** The privacy check scanned
   `tests/fixtures/` but not `tests/*.py`, and the leaked values lived in a
   test module (`tests/test_connection.py`), not a fixture.

2. **The IPv4 regex failed on four-octet addresses.** The original pattern
   ended with a boundary assertion that excluded the final dot, so it matched
   three-octet fragments but silently skipped full addresses such as the leaked
   private IP. In other words: three-octet IPs were caught, four-octet IPs
   were not.

A third gap — the check had no notion of the local username at all — meant
that a bare username would never be flagged regardless of the other fixes.

## Remediation

- Rewrote the privacy check as a Python script (`scripts/privacy_check.py`).
- Corrected the IPv4 detection to use `ipaddress` for precise private/reserved
  range matching, and to skip CIDR block definitions explicitly.
- Added a dynamic `$USER` blacklist so the local username is always checked.
- Expanded the scan scope to the entire `tests/` directory.
- Force-rewrote the public history to remove the identifiers, then re-published
  all branches and tags.
- Enabled branch protection on `main` (no force pushes, no deletions, status
  checks required).

## Prevention

- `privacy-check` runs in CI on every push and pull request.
- `make privacy-check` runs the same check locally before opening a PR.
- Test fixtures must use placeholder values (e.g. `user`, `10.0.0.1`,
  TEST-NET ranges); a whitelist in the check encodes these conventions.
- This document is retained as a permanent record.

## Note on Public History

Because the identifiers were already visible on the public remote, rewriting
the repository history removes them from all live refs. GitHub's garbage
collection reclaims unreferenced commits over time; until then, the old commit
objects are not reachable by browsing or search and are only retrievable by a
known, no-longer-published hash.
